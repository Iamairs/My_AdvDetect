# 实验记录

## 2026-10-24：迁移资源与 GPU 冒烟验证

- **目标**：将 `CCDE-ID_AdvDetect` 中的 CIFAR-10、CIFAR ResNet18 权重和层回归实现接入当前研究工程，并验证统一实验流程。
- **代码与资源**：资源导入脚本为 `scripts/common/import_resources.py`；模型实现位于 `src/advdetect/models/backbones.py`；资源哈希记录于 `docs/resource_manifest.json`。
- **环境**：Conda 环境 `cv_env`；PyTorch `2.5.1+cu121`；torchvision `0.20.1+cu121`；torchattacks `3.5.1`；NVIDIA RTX 3050 Laptop GPU。
- **验证命令**：
  - `python -m unittest discover -s tests -v`
  - `run.py check-resources --config configs/experiments/baselines/msp/cifar10_msp_smoke.yaml`
  - `run.py run --config configs/experiments/baselines/msp/cifar10_msp_smoke.yaml`
  - `run.py run --config configs/experiments/baselines/lr/cifar10_lr_smoke.yaml`
- **结果**：8 个单元测试通过；资源检查通过，设备为 CUDA，输入梯度非零，资源哈希全部匹配。MSP 和 LR 冒烟流程均完成拟合、攻击生成/缓存复用、校准和评价。
- **关键指标**：MSP 冒烟 AUROC（成功攻击子集）为 `0.3437`，攻击绕过率为 `0.9381`；LR 冒烟 AUROC 为 `0.7075`，攻击绕过率为 `0.6372`。样本量仅为 128，LR 只训练 1 轮，因此这些数字仅说明流程可运行，不代表论文结论。
- **产物**：对应运行目录为 `outputs/20261024_154542_run_4ea550` 和 `outputs/20261024_154619_run_cb17a6`；攻击缓存位于 `cache/attacks/`，检测器权重位于 `checkpoints/detectors/`。
- **限制与后续**：当前验证使用 CPU 默认环境会因 torchvision 与 PyTorch 不匹配而失败，应固定使用 `cv_env`。后续需在正式数据划分、独立调参/校准集和完整攻击协议下复现实验，并补充自适应攻击及更多基线。

## 2026-10-24：重启后复测原始 float32 torch.cat 方案

- **目的**：按用户要求重启电脑后，恢复原始 batch 列表 + `torch.cat` + float32 缓存方案，验证清理系统内存是否足以完成完整 CIFAR-100/ResNet50 PGD。
- **运行**：`outputs/20261024_220201_evaluate_8dd07e`；重启后可用物理内存约 `16.1 GiB`，batch size `16`，完整测试集 `10,000` 张。
- **结果**：PGD 攻击生成阶段完成 `10000/10000`，但进程在生成结束后的 `torch.cat`/缓存阶段退出，未生成 traceback、attack cache 或 metrics；运行元数据仍为 `status: running`，说明进程被系统直接终止而非 Python 异常处理。
- **判断**：原始方案的列表已同时保留约 `11.2 GiB` 的 clean/adversarial float32 数据，`torch.cat` 还需申请新的连续张量，峰值超过当前可用内存。重启和清理后台程序不能稳定解决该峰值问题。
- **后续**：若要完成正式指标，应使用分 batch 的 float32 磁盘缓存/流式评价；该方案不改变 PGD 计算精度，但需要调整评价流程以避免再次把全量图像加载到内存。

## 2026-10-24：实现分 batch float32 磁盘缓存与流式评价

- **代码**：`src/advdetect/experiments/workflow.py` 新增 `advdetect_attack_stream_v1` 缓存格式。对抗样本以 float32 写入 `adv_images.float32.bin` memmap，标签和样本索引单独保存；clean 图像在评价时从测试集按 batch 重新读取。
- **断点**：每个 batch 写入并 flush 后更新 `manifest.json` 的 `completed_batches`。同一绑定下的未完成缓存可继续生成，完整缓存可直接复用。攻击随机种子改为按 batch 固定，保证续跑时后续 batch 可复现。
- **评价**：按测试集顺序逐 batch 读取缓存，计算 LR 分数、分类预测和 `max_linf`；只在 CPU 内存中汇总分数、标签和预测，不再加载全量图像。
- **验证**：10 个单元测试通过；32 样本 PGD 生成、缓存复用和完整 `run` 闭环通过。测试中 `max_linf=0.03137258`，符合 `epsilon=8/255`。旧的全量 float32 `.pt` 缓存格式不再由新流程复用。
- **正式实验命令**：`python run.py evaluate --config configs/experiments/baselines/lr/cifar100_lr_pgd.yaml --detector-checkpoint checkpoints/detectors/20261024_193951_fit-detector_d8ab72/detector.pt`。新缓存预计占用约 `5.6 GiB` 磁盘空间，评价阶段不需要一次性申请全量图像内存。
