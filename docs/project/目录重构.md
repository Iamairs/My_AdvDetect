# 2026-10-30 目录重构

为避免方法、跨方法研究和公共维护工具混放，本次整理了脚本、实验配置、方法参数、攻击配置、模型配置、参数扫描、方法/研究文档、测试、历史实验记录和研究额外依赖。

## 归属规则

1. 方法专用：`methods/<方法>`，配置按`baselines`或`proposed`区分。
2. 多方法比较/诊断：`studies/<研究问题>`，对应四组P0/P1与后续研究。
3. 分类器训练：`scripts/training/lr`与`jad`。
4. 公共维护入口：`scripts/common`；公共数据/模型/攻击/评价仍在`src/advdetect`。
5. 方法的Python实现已经在各自模块中分离，不为迁目录改写算法。已有字节绑定的32个研究/模型/检测器源码文件保持不变。
6. 原16节实验记录按项目、方法和研究问题保存，根`实验记录.md`作为索引和项目变更记录。

原地址到新地址的完整对应见[迁移表](layout_migration.json)。本机忽略的JAD监控脚本归入`training/jad/local`并修复根目录发现，仍不上传。

## 兼容与验证

- 迁移前后39份原YAML的完整展开值逐一比较一致；扫描配置中的实验地址按等价新地址比较。方法参数从组合配置拆出后仍一致。
- 35个旧配置地址通过`configs/legacy_paths.yaml`统一映射到新文件；`load_config`只在旧文件不存在时使用映射，保留CLI覆盖与循环继承检查。
- 旧脚本路径不留一排兼容副本；维护文档和跨脚本导入统一使用新地址。
- 从项目外工作目录启动时，入口按`pyproject.toml`和`src/advdetect`识别项目根。
- 模型/方法参数、输入归一化、数据切分、攻击预算、分数方向和阈值不变。
- 数据、权重、缓存及既有运行目录保持原位，不上传GitHub。历史运行保存的旧脚本地址作为当时的出处保留。
- `.gitattributes`固定源码与配置LF换行，避免Windows/Linux检出转换使检查点的源码哈希失效。

资源检查还修复了一项历史清单归类问题：骨干源码的导入时记录原样保存在`source_snapshots`，`files`只包含不可变数据和权重。这些资产仍严格核对原哈希；当前源码由运行/检查点绑定。没有改写当时的源码哈希，也没有修改工作流文件使旧攻击缓存重新失效。

具体完成的验证和Git提交见根目录[实验记录索引](../../实验记录.md)。目录验证没有启动长时间拟合、分类器训练或新攻击实验。
